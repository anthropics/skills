## Codex decision procedure

1. Match user intent to the categories and search hints above; rank up to three repositories.
2. Use GitHub access or a local checkout to inspect the **actual** README, `SKILL.md`, license, setup instructions, security notes, tests, and APIs.
3. Check whether the chosen project is a usable Codex skill, a Claude-only plugin, an MCP server, an example, or a full application. Integrate it only through a supported mechanism; adapt incompatible formats rather than assuming portability.
4. Prefer an already configured capability. If none is installed, explain what configuration and credentials are needed; never claim a repository is available as a running tool merely because it is forked.
5. For tasks needing several capabilities, choose a primary tool and only necessary supporting tools. Avoid loading all repositories into context.
6. Before executing third-party code, assess licenses, dependencies, supply-chain and permissions risks. Require approval for dangerous actions or live transactions.
7. Record verified findings and test results, with repository revision and date, in a future audited catalog update.
