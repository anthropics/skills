# Requirements Review

코드를 수정하지 않고 요구사항 충족 여부만 검토한다.

## 검토 절차

1. 원래 요구사항, 완료 조건, 허용 범위, 금지 범위를 분리한다.
2. 각 요구사항에 짧은 식별자를 붙인다.
3. 변경 파일, 테스트, 문서에서 각 요구사항의 구현 증거를 찾는다.
4. 각 항목을 `PASS`, `FAIL`, `REVIEW`, `OUT_OF_SCOPE` 중 하나로 판정한다.
5. 요구하지 않은 동작이 추가되었거나 기존 동작이 사라질 위험도 확인한다.

요구사항에 없는 제품 정책, 권한 규칙, 기본값을 임의로 가정하지 않는다. 구현이 합리적으로 보여도 사용자 합의가 필요한 결정은 `REVIEW`로 남긴다.

## 출력 형식

먼저 전체 상태를 `PASS`, `FAIL`, `REVIEW` 중 하나로 적는다. 이어서 요구사항별로 다음 내용을 기록한다.

- 요구사항 ID와 내용
- 판정
- 파일, 줄, 테스트 결과 등의 증거
- 누락 또는 불일치가 만드는 영향
- 필요한 확인이나 권장 조치

스타일 취향이나 구현 선호는 기능 요구사항처럼 보고하지 않는다. 증거가 없는 추측은 명확히 추측으로 표시한다.
