# 散户大佬反人性市场分析仪表盘（Retail Master Dashboard）

## 用途

把「散户大佬」专家（反人性市场分析师）的分析结论渲染为一份深色终端风格的 HTML 仪表盘。核心世界观：价格是微观交易行为长出来的宏观涌现，不预测点位，只诊断结构——这个价格是谁、在什么情绪下做出来的，人群的人性错误在哪，反着站的安全边际在哪。

## 触发条件

- 用户要求对大盘/板块/个股做「反人性分析」「相态诊断」「人群情绪分析」并输出报告
- 用户要求「按这个风格生成分析」「输出分析仪表盘」「生成散户大佬报告」
- 与 retail-master 专家配合使用时，作为其最终输出载体

**明确排除**（这些场景应激活其他能力，不要误触发本skill）：
- 「查一下行情」「现在多少点」等纯数据查询——直接用行情API回答即可
- 「帮我筛选/选股」「按ROE排名」——属于选股筛选类工具
- 「预测明天涨跌」等短线点位预测——与本skill「只诊断结构不预测点位」的世界观冲突，除非用户明确要反人性分析框架

## 硬性合规约束（每次必须检查，不可省略）

1. **不给买卖指令**：全文只输出「若X信号出现→考虑Y方向」的条件框架，禁止出现 buy/sell/目标价/必涨必跌等确定性表述
2. **免责声明强制**：每份输出末尾必须附 `本内容仅为信息整理与分析参考，不构成投资建议，投资有风险，决策需谨慎。`
3. **不传递内幕信息**，不泄漏用户持仓画像
4. **生成论框架是启发式不是严格数学**，输出中不得夸大确定性
5. **禁止裸逆势扛单表述**：等相变确认信号是反向操作的硬前置条件，确认前只能"准备"不能"执行"
6. **禁止用训练数据回答行情情绪类问题**：强时效数据必须实时取数，取不到就在报告中明说并降级处理

## 能力边界（先明确预期，避免数据幻觉）

| 范围 | 支持度 | 说明 |
|---|---|---|
| A股大盘/板块/个股 | ✅ 完全支持 | 腾讯/东财接口行情+资金流均可实时取 |
| 港股大盘/指数（恒指/恒科） | ⚠️ 部分支持 | 报价、52周高低、YTD、涨跌幅可实时取；融资余额/社媒情绪等情绪面数据受限，用南向资金净流向+主流财经媒体新闻交叉验证替代，并在报告中标注降级 |
| 美股/其他海外市场 | ❌ 基本不支持 | 仅能取到报价类数据，六维采集多数维度缺失，原则上婉拒并说明 |
| 情绪类精确分位（20日波动率分位、新开户数） | ⚠️ 常缺失 | 取不到就标 `unavailable` 并把相态置信度压至50%以下，禁止编造 |

## 工作流程

### Step 0 环境探测（不要假设数据源存在，先探测再决策）

```bash
# ① Python与akshare（决定能否走本地计算路径）
python -c "import akshare" 2>/dev/null && echo "AKSHARE_OK" || echo "AKSHARE_MISSING"
# ② 腾讯行情API连通性（本机实测可用的兜底主路径）
curl -s "https://qt.gtimg.cn/q=sh000001" | head -c 200
```

数据源降级链（按序尝试，命中即用）：

1. `neodata-financial-search` / `westock-data` MCP工具（若已安装）
2. `akshare`（A股财务/资金流计算；注意成交额单位为**万元**须÷10000）
3. **腾讯行情API直连（本机实测兜底主路径）**：`curl -s "https://qt.gtimg.cn/q=hkHSTECH"`，GBK编码需转UTF-8；一次返回最新价、涨跌幅、52周高低、YTD涨幅、振幅等。常用代码：A股`sh000001/sz399001/sz399006`，港股`hkHSI/hkHSTECH/hkHSCEI`，美股`usAAPL.US`格式
4. **WebSearch新闻交叉验证**：资金流向、情绪面、事件催化剂用多源新闻拼图（东财/新浪/雪球/财联社），每条标注来源

### Step 1 实时取数（六维现象采集）

| 维度 | 典型指标 |
|---|---|
| 量价 | 量比、换手率、成交额 |
| 波动 | 20日波动率及其历史分位 |
| 情绪 | 融资余额变动、新开户数、社媒热度 |
| 资金 | 主力净流入、北向/南向成交活跃度 |
| 伤疤 | 上方套牢密集成交区、下方成本支撑区 |
| 外场 | 信息场/情绪场/资金场三大外场信号 |

**数据口径注意（易错点）**：
- akshare 成交额单位为**万元**，须 ÷10000 转亿元
- 北向资金自2024年起仅披露成交总额，无实时净买入，用「成交额趋势+重仓成交股」刻画活跃度；港股用南向净买入刻画
- 每个数据标注来源与截止时间，并打数据质量标记（见 Step 5 质量标记规范）

### Step 2 判相态

按八大相态（冻结/解冻/活跃/沸腾/崩塌/阴跌/虚高/震荡）归类，输出：**相态 + 置信度 + 判据**。每条判定必须附数据水位（哪几个指标处于什么分位），不允许拍脑袋归类。数据不足以判定时置信度压至 50% 以下并说明缺哪些判据。

### Step 3 反推资金行为

判断量价是谁做出来的：主力（低吸建仓还是进攻拉抬）、游资（蛰伏还是点火）、散户（割肉还是追高）。附伤疤结构与反身性链条定位（处于"事件→推价→共识→共识变事实→反噬"第几环）。

### Step 4 反人性对照

扫描三大外场做 0-100 情绪温度计（0极端恐慌/100极端亢奋，极端值是反向指标但需确认）。识别人群当前人性错误（回本焦虑、错失恐惧、恐慌抛售、习得性无助），查「现象→反推→人群做错→反向动作」映射。

### Step 5 生成 HTML（v1.3 静态版式）

复制 `assets/retail_master_analysis_template.html` 到工作区，重命名为 `retail_master_analysis_YYYYMMDD.html`（YYYYMMDD=数据日期）。**模板为纯静态HTML（无JS），样式与版式结构原样保留，只替换文字与数据**。逐区块替换：

| 区块 | 替换内容 |
|---|---|
| Hero（页首大卡） | 分析对象、一句话结论（.concl）；相态大字+置信度（`.cfbar i` 的 width 同步改为置信度数值）；**证据条四行**（.qrow）：标签（估值/资金/盈利/反身性）+纯进度条，**无中间文字列**——条长编码正负（长=正面/蓝、短=负面/橙、中性绿），详细判读留给下方各节，不在Hero重复 |
| 01 KPI六卡 | 数值、涨跌、来源；涨红`.upk`跌绿`.dnk`中性`.nn`，顶部色条随语义切换 |
| 02 六维判据表 | 每行附质量标记；表格下方降级说明（如有unavailable项） |
| 03 资金三卡 | 主力/游资/散户：现象+动作解读两段（.lbl标签分段），配色 m1红/m2橙/m3绿，底部行为指纹行 |
| 04 反身性链条 | 五节点文字；`.cnode.on` 移到当前环；链条注解（.note）一句化 |
| 05 温度计三卡 | 数值改 `.tv` 文本与 `.dot` 的 left 百分比；档位class：t-low(<35)/t-mid(35~70)/t-high(>70)；判读项短句化 |
| 06 相态轨道 | `.pseg.on` 移到当前相态；判据注解压成一行分点式 |
| 07 价格梯 | **核心可视化**：纵轴按标的实际区间改写（参考轴距：52周低点向下5%余量为底、高点向上3%为顶）；**双层网格**（主格线每500点一档较亮#3b4f70、细格线每250点一档#26344e，用repeating-linear-gradient实现）+左轴刻度标签（每500点一档、12px、居中对齐横线）；`.zone.res`（套牢压力，红）与 `.zone.sup`（支撑，绿）的 top/height 按 `（价位-轴底)/轴距` 百分比计算；`.pline` top=现价位置，`.pv` 改现价 |
| 08 三情景卡 | 条件→动作条→确认信号三段式；条件与信号各压到两行内 |
| 09 风控触发点 | 四级：第一预警/减仓线/资金预警/硬止损区，数字按实际数据计算 |
| 全会总结 | verdict大句+四行（核心句/谁在做什么/反向框架/铁律自检），每行压缩到一两短句 |
| 页脚 | 免责声明+数据来源清单+质量标记图例 |

**质量标记规范**：每个数据点后缀〔A〕actual接口实测/〔D〕derived由实测推算/〔E〕estimated新闻口径转述/〔unavailable〕未取得。页眉图例与页脚来源清单同步列出。核心论点的置信度跟随其最弱数据源：〔E〕级数据不得单独支撑核心结论，须有〔A/D〕级数据或多源交叉佐证。

**风控触发点默认参数**（用户策略参数可覆盖）：

| 触发点 | 默认定义 |
|---|---|
| 第一预警 | 跌破近8周震荡平台下沿 |
| 减仓线 | 平台再向下3%~5%，或关键资金流指标连续3日反向 |
| 硬止损 | 52周低点失守，年度相态判断作废重新诊断 |
| 资金预警 | 单日主力/南向净流出超近期流入均值单日峰值，无论价格位置先降敞口 |

### Step 6 输出

用 present_files 展示最终 HTML。文本回复中给出：相态结论一行 + 谁在做什么一行 + 最重要的反向框架一条 + 免责声明。

**输出前自检清单**：
- [ ] 六条合规约束逐条过（尤其无 buy/sell/目标价字样）
- [ ] 每个数据有来源+截止时间+质量标记
- [ ] 取不到的指标已标 unavailable 且相态置信度相应下调
- [ ] 模板中旧数据全部替换，无上一份报告的残留文字
- [ ] 全文无内联`<b>`加粗（强调靠颜色/标签/版式承载，见红线）
- [ ] 图表类区块（价格梯）网格线与刻度标签齐全
- [ ] 免责声明在 HTML 末尾与文本回复中均出现

## 视觉规范（v1.3 静态版式）

**基础盘**：
- 深色背景 `#0a0f1a`，卡片 `#101828`，涨红 `#ff5a6e`、跌绿 `#2bd39c`（中国习惯，不可颠倒）
- 正文基准15px、行高1.8；数字统一 `.num` 等宽字体；表格化优先于大段文字
- 章节头统一「渐变编号徽章（01~09）+21px粗标题+灰色副标题」，副标题一句话点明读法

**版式结构（自上而下）**：Hero（一句话结论+相态大字/置信度+证据条四行：标签+纯进度条无文字）→ 01 KPI六卡 → 02 六维判据表 → 03 资金三卡 → 04 反身性链条步进器 → 05 三温度计（渐变刻度+游标）→ 06 八相态轨道 → 07 价格梯（双层网格+套牢/支撑带）→ 08 三情景等宽卡 → 09 四级风控 → 全会总结大卡（渐变标题栏）→ 页脚免责+来源

**可读性红线（用户多轮反馈沉淀，必须遵守）**：
- 正文叙述类文字最低亮度 `#c6d2e4`，说明文字最低 `#a7b6cc`，重要结论 `#d8e7fb`~白；禁止更低亮度承载正文
- **全文禁止内联`<b>`加粗**：强调靠颜色、标签徽章、版式承载，不用字重
- **图表类区块（价格梯等）必须带网格线与刻度标签**：主格每500点（或标的合理步长）一档，刻度标签12px居中对齐横线
- 说明性文字字号下限12px，判读项13.5px+，行高不低于1.7
- 文案要精简直接：判读用分点式短语（「南向628亿・环比翻倍」）不用整句铺陈；副标题砍掉重复套话；情景条件与确认信号各两行内；Hero不重复正文已有的详细判读

**响应式**：<900px 三列改单列、链条步进器转纵向；<560px KPI改两列、相态轨道换行。

## FAQ / 避坑指南

- **开了代理取数失败？** 腾讯/东财接口需国内直连，开代理反而失败，提示用户或改走 WebSearch
- **非交易时段？** 接口返回上一交易日收盘价，报告中数据截止时间写清「收盘」
- **港股情绪数据缺失？** 不要编造，用南向资金+新闻交叉验证替代并标注降级
- **YTD/52周数据从哪来？** 腾讯行情API字段直接含（第45~48字段位为52周高低等），无需另算
- **价格梯区间怎么定？** 以52周低点向下留5%余量为轴底、52周高点向上留3%为轴顶，套牢/支撑带按真实成交密集区换算百分比；网格与刻度必须同步换算

## 三条铁律（每次检查）

1. 做龙头不做杂毛
2. 不追已知信息
3. 警惕"共识变事实"
