# code-review — AI生成代码的七维审查

一句话总纲：**审计修复分离**——review = 只读，出问题清单，证据不足不写结论，确认后才动手修。清单为「懂产品但少逐行读代码的人」服务：每条先说白话影响（你会感觉到什么/不修会怎样），再给「建议修/可缓/不必」档位。

## 为什么需要它

AI 写的代码有四类人写代码不常有的病：调用了不存在的API（幻觉）、`except: pass` 吞掉错误悄悄给默认值（静默降级——表面正常，数据已错）、20行需求搭三层抽象（过度工程）、项目里已有轮子又造一个（重复造轮子）。这些病代码外观上看不出来，需要专门的审查清单逐条扫。

## 七维检查清单

| # | 维度 | 扫什么 |
|---|---|---|
| ① | 正确性 Bug | 边界反例（空/None/单元素/极值/NaN/跨日）、Windows路径、中文编码GBK乱码、时区、数据口径 |
| ② | 幻觉与静默降级 | 幻觉API签名、except:pass黑名单、无质量标记的降级、幻觉配置项 |
| ③ | 性能与资源 | 循环内IO/new、句柄未关、大文件全量进内存、外部调用无超时、无profile数字的「变快了」 |
| ④ | 冗余、一致性与可维护性 | 死代码（须全库Grep确认）、调试残留与TODO、≥3处重复才提取、重复造轮子、_v2/_final后缀文件；量化基线：函数>30行、嵌套>3层、参数≥4、魔法数字、类>500行、Manager/Utils空壳命名、泛名黑名单 |
| ⑤ | 安全与泄漏 | 硬编码密钥、SQL拼接、日志打印敏感信息 |
| ⑥ | 产品与过度工程 | 删除测试（删掉会坏吗）、空壳基类、数据没就位硬凑半成品 |
| ⑦ | 可验证性与可回滚 | 无对比基准的盲改、无测试覆盖、「应该能跑」式交付 |

严重度排序铁律：**正确性 > 安全 > 可维护性 > 简单性 > 性能 > 优雅性**。

## 工作流

1. 环境探测：全文读目标文件（禁只看片段）、Grep全项目引用、记录运行环境；多模块拆开审，每模块给进度锚（「✓ 模块A完成，N条，下一个：B」），中断续跑不重扫
2. 七维逐条扫描，可疑API查官方签名或本地实测；大仓库可按维度/模块派只读子代理并行扫——但子代理报告是「声称不是证据」，入清单前复核行号、去重、剔误报、计数对账
3. 认定的bug证伪一次：构造反例（空值/极值/跨日/停牌）试图推翻自己
4. 输出问题清单，**停**，等用户确认。每条五字段：定位 / 根因 / 影响（白话一句+术语，说清「不修会怎样」）/ 维度+严重度 / 修复方向+建议档位（建议修/可缓/不必）；末尾收尾三段：分档统计+未扫范围声明 / Quick wins（≤5分钟小修单列，便于先批） / 热点文件TOP3
5. 结论里出现「应该能跑/大概没问题/肯定没人用」式模糊措辞=该处缺验证，红旗打回；执行中冒出的走偏念头（顺手修、抽查代替全扫、直接抄子代理结果）用「借口反驳表」逐条打住
6. 用户确认后切正常编码流程修复（本skill不负责修复）

## 适用边界

管「只读审查出清单」；不管修复实施、不管渗透测试级安全审计、不管性能调优代跑、不管skill写作。

## SkillHub 案例填写参考

**案例标题**：code-review — AI代码七维审查·只出清单不动手修

**适合人群**：用AI写代码的开发者（Claude Code / 千问办公 / Cursor用户）、接手AI生成代码要把关的工程师、交付前想多一道质检的独立开发者。

**能解决的问题**：AI代码「看起来对」但跑不通（幻觉API）；出错了不报错悄悄给默认值，表面正常数据已错（静默降级）；review报告泛泛而谈没有定位行号和证据；AI顺手改一堆无关代码（本skill审计修复分离，只读）。

**使用步骤**：
1. 触发skill：说「review代码 / 代码体检 / 帮我把关代码质量」
2. 给出代码（粘贴或文件路径），可指定重点维度
3. AI按七维清单只读扫描，输出问题清单（定位+根因+影响+严重度+修复方向）
4. 确认要修的条目后，AI才进入修复流程

**使用Prompt（可直接粘贴到对话框，选中{{}}内文字设为占位词）**：

> 请用 code-review skill 审查以下代码：
>
> 代码：{{粘贴代码或文件路径}}
> 语言/运行环境：{{如：Python 3.11 / Windows}}
> 重点关注：{{如：性能/安全/AI幻觉与静默降级/全部七维}}
>
> 按「审计修复分离」执行：只读不改，输出问题清单（定位文件:行号+根因+影响面+严重度+修复方向），我确认后再谈修复。
