# Code Review

현재 변경을 읽기 전용으로 검토한다. 코드를 수정하거나 포맷하지 않는다.

## 검토 범위

다음 항목을 우선한다.

- 요구한 동작과 실제 제어 흐름의 불일치
- 인증과 권한 우회
- 입력 검증, 비밀 정보 노출, 주입 등 보안 문제
- 저장, 조회, 기본값, 기존 데이터 처리의 불일치
- 오류 처리와 경계 조건
- 기존 기능의 회귀 가능성
- 테스트가 통과해도 드러나지 않는 서비스 로직 결함

기능, 안전성, 유지보수에 실제 영향을 주지 않는 스타일 취향은 보고하지 않는다.

## 검토 절차

1. 저장소 지침과 원래 요구사항을 읽는다.
2. 변경 diff와 직접 연결된 호출 경로를 확인한다.
3. 발견마다 재현 가능한 조건과 코드 증거를 확보한다.
4. 기존 테스트가 발견을 반박하거나 이미 보호하는지 확인한다.
5. 심각도를 `CRITICAL`, `HIGH`, `MEDIUM`, `LOW` 중 하나로 정한다.

## 출력 형식

발견이 있으면 심각도 순으로 다음 내용을 작성한다.

- 제목
- 심각도
- 파일과 줄
- 발생 조건
- 현재 동작과 기대 동작
- 영향
- 최소 권장 조치

발견이 없으면 `PASS`라고 쓰고 확인한 범위와 남은 검증 공백을 적는다. 증거가 부족한 항목은 결함으로 단정하지 않고 `REVIEW`로 분리한다.
