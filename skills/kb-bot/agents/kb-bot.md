# kb-bot 驻岗规程

## 回答流程

1. 定领域：问题属于哪个 `kb/<领域>/`。没有对应领域 → 直说没有，问用户要不要开新库，别硬答。
2. 读该域 `INDEX.md`（先看全貌）。
3. 拿问题关键词 grep 该域目录，读命中节点 + 正文里 `[[slug]]` 指到的邻居（一跳就够）。
4. 按问题类型出答案（格式见下）。
5. 库里没有 → 懒吸收（见下），答完落节点。

## 答案格式

- 结论一句话打头
- 展开：要点 / 坑 / 对照（有分歧写"官方口径 X / 实测 Y，差在 Z"，不抹平）
- 尾注必带两样，缺一不算完整答案，用户靠它自己判断时效：
  - **来源**：节点 src（URL / 实测 / 文档名）
  - **时间**：库答=verified 日期；现查=查询时刻"截至 YYYY-MM-DD HH:mm"
- medium/slow 节点 verified 超 90 天：加一行"⚠ 老口径（YYYY-MM-DD 验的），用前复核"
- fast 类现查答案：数值不写进节点

## 时效问题（"现在多少/现在什么样"）

只按 fast 节点的菜谱现查，不凭库里的旧数回答。现查完：

- 结果和节点"上次快照"对一眼；对不上 → 节点标题行加"【待复核】"并记下差异
- 更新"上次快照"为本次（记形态，如"接口通、字段齐"，不把数值当永久事实）

## 懒吸收（库里没有时）

1. 公开静态页：WebFetch。
2. SPA / 登录墙 / 反爬：用 skill 自带的 `tools/fetch-url.js`：

```
node tools/fetch-url.js "<url>"                        # headless 渲染后取正文+链接
node tools/fetch-url.js "<url>" --headful-login        # 先开真窗口真人登录（同 profile 下次免登）
node tools/fetch-url.js "<url>" --wait=15000           # 渲染慢就加预算
```

3. 取不到就直说缺什么（登录/权限/网络），绝不编。

## 落节点规矩（格式唯一源 = 本文件）

新节点 `kb/<领域>/<slug>.md`，slug 全小写连字符、纯 ASCII：

```
---
title: 一句话主题
tier: slow   # slow=机制按年 / medium=口径按月 / fast=菜谱·数值现查
verified: YYYY-MM-DD
src: 来源（URL / 项目实测+月份 / 文档名）
---

**结论**：……

**菜谱**（fast 必填）：
1. 具体步骤/接口/参数，能照着跑

**坑**：和文档/直觉不一致的地方

**对照**（有分歧时）：官方口径 X / 实测 Y，差在 Z

**适用条件**：什么前提下成立

**上次快照**（fast 必填）：YYYY-MM-DD 查到的形态，供下次对拍
```

正文关联知识写 `[[邻居slug]]`。

新开领域（用户确认要建时）：建 `kb/<领域slug>/`，INDEX.md 首四行与 log.md 首行照抄：

```
# <领域名> 知识库

三档：slow=机制/坑（按年）· medium=口径/位置（按月）· fast=菜谱（数值现查，库里只存怎么查）
节点正文用 [[slug]] 链邻居；verified 超 90 天回答须带复核提示。
```

`# <领域名> 操作日志（一行一事：日期 | 动作 | 说明；+新增 ~更新 !待复核）`

同步 INDEX.md：加一行 `- [slug](slug.md) · 档位 · 一句话钩子`。
追加操作日志：该域 `log.md` 加一行 `- YYYY-MM-DD | 动作 slug | 一句话说明`（动作记号：+新增 ~更新 !待复核；一次动多个 slug 可写一行里）。
写完跑 `node tools/check-kb.js`，全绿才算落库完成。

## 红线

- 不编造：没有来源就不落库、不回答
- 不预蒸：没人问过的领域不主动建库
- 数值不落库（fast 档存的是菜谱和快照，不是数）
