# Frontend Design

## Domain Grounding and Context Resolution

- Extract the product identity, target audience, and primary functional objective from each parameter in the input brief and allocated context memory.
- Formulate a proposed specification defining one concrete subject domain, target audience, and primary functional objective for user verification on each input brief with open subject parameters.
- Derive each visual token, typographic selection, and spatial structure from the industry vernacular, physical materials, and functional mechanics of the subject domain.
- Prioritize each explicit visual directive in the input brief over default aesthetic diversification rules across the design specification.

## Pre-Implementation Specification and Calibration

- Construct a pre-implementation design specification prior to source code generation across each of the 4 core token categories: 4 to 6 named hex color values, 1 or 2 role-mapped typeface families, single-sentence spatial layout descriptions paired with ASCII wireframes and horizontal alignment axes, and brief-specific visual differentiation principles.
- Audit each token in the pre-implementation design specification against the input brief and replace each generic template token with a domain-specific alternative accompanied by its modification rationale prior to code generation.

## Layout Architecture and Focal Hierarchy

- Anchor each primary hero viewport with the core characteristic artifact of the subject domain through a headline, domain visual, interactive module, or live demonstration, isolated from default oversized numeric counters paired with supporting statistics and gradient accents.
- Calibrate each surface palette and spatial grid to the subject domain, isolated from default #F4F1EA cream surfaces with #D97757 terracotta accents, #0B0B0B or #111111 dark surfaces with acid-green or vermilion accents, hairline-ruled newspaper broadsheet columns, and uniform rounded card grids with rgba(0,0,0,.1) drop shadows.
- Concentrate visual weight on one primary focal component within each viewport and retain strictly interface components that execute a direct functional role in the input brief.
- Assign each structural border, outline, eyebrow, and divider strictly to encode content hierarchy and relational grouping across interface components.
- Restrict each sequential numeric marker such as 01, 02, and 03 to ordered multi-step workflows and chronological timelines.

## Typographic Scale and Structural Formatting

- Select 1 typeface family or 2 clearly distinct typeface families matched to the subject domain and define each level of the typographic scale across weight, width, and spacing parameters according to The Elements of Typographic Style.
- Configure each body copy block to a line length below 80 characters and assign expanded line-height ratios with extended line lengths to each serif body copy block relative to sans-serif body copy.
- Integrate each display headline as an active structural element of the layout composition, isolated from single-word italic, bold, or color highlights inside headlines, uppercase eyebrow labels, middle-dot metadata strings, spaced em-dash label fragments, monospace secondary data tags, and trailing arrow glyphs on interactive triggers.

## Motion Choreography and Style Isolation

- Bind each animated transition to a single coordinated page-load reveal or a user-triggered state change, isolated from repetitive section entrance fades and uniform card hover transitions.
- Isolate each container-level layout selector such as .section from each component-level element selector such as .cta across CSS rulesets, maintaining orthogonal margin and padding declarations.
- Enforce baseline technical compliance across each rendered viewport covering mobile-to-desktop responsive breakpoints, visible keyboard focus rings, prefers-reduced-motion media query support, and accessible color contrast ratios.
- Inspect each rendered viewport through visual screenshot capture when supported by the execution environment and log each executed design pattern into allocated context memory across iterative passes.

## Interface Copywriting and State Signaling

- Construct each interface copy element in sentence case using active verbs and domain-aligned tone where each text node executes a single navigational or informational function.
- Label each interface control using end-user functional terminology, isolated from internal system implementation nomenclature:
  + Webhook config ➔ Notifications
- Specify the exact operational outcome on each interactive trigger using a concrete action verb, isolated from generic form submission labels:
  + Submit ➔ Save changes
- Maintain identical action terminology between each interactive trigger and its corresponding state confirmation notice across the interaction flow:
  + Publish ➔ Published
- Formulate each error notice and empty-state prompt by stating the exact system condition and the required user action in objective interface language, isolated from apologetic or emotive phrasing.
