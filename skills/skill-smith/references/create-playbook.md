# 生成流程（九步锻造·骨架→自检闭环）

> 依据：高质量skill设计指南四原则（先诊断再设计/实证优先于假设/判断类逻辑双轨/纪律必须可触线）+ 八条模式。产物按 templates/skill-skeleton.md 骨架出。

## 第0步 接需求（≤2轮追问）

- 复述定位一句话，用户点头才动工；复述费劲=需求太糊，这轮只问需求本身。
- 只问「答案不同、skill 就不同」的题：给谁用/什么场景触发/交付什么/边界在哪/怎么算好用。
- 追问到顶（2轮）后用默认假设继续，产物顶部声明「以下基于假设X」。
- 一次性提示词需求 → 转交 prompt-forge，不接。

## 第1步 定位与边界

- 一句话定位：动词开头，说清「给谁、在什么场景、交付什么」。
- 能力边界三栏表：能做／不能做（指向替代方案）／高危动作（须用户确认）。

## 第2步 触发面

- 双向触发表：「用我」场景清单 + 「别用我」排除区（写进 description）。
- 触发词清单：用户会怎么说出这个需求，原话级别列 10-30 个。
- description 硬限 1024 字符：触发词+排除区优先，机制描述压缩；超了砍机制描述不砍触发词。

## 第3步 路由架构

- SKILL.md＝定位+速查+流程骨架+纪律表+索引表；细节全下沉 references。
- 每个 reference 一句话职责，索引表写明「什么任务读哪个文件」。
- 三层阅读路径：速查（30秒上手）→ 正文流程 → references（深究）。

## 第4步 纪律数字化表

- 逐条纪律写成「场景｜数字上限｜到顶后动作」三列。
- 元纪律：写不出数字上限的纪律不许写。重试/澄清/加载/探索类必须全表覆盖。

## 第5步 关卡设计

- 列出全流程的「门」：哪步人拍板（确认门）、哪步机检（质检门，不过=回炉/中止）、哪步危险（高危门）。
- 每扇门写明「不过的后果」，不留「尽量注意」。

## 第6步 诚实状态

- 定证据标签：哪些输出带 [已验证]/[推断]/[待核实]。
- 定失败态：脚本失败/数据缺失/拿不准时，各输出什么、取不取低一级结论。
- 禁静默降级：降级必须明说降到哪。

## 第7步 预期管理

- 负面承诺清单：明确不做什么（3-6条）。
- 效果承诺三件套：设计目标 + 不承诺X + 可验证指标（能算出来的数字，不算出来的不写）。

## 第8步 骨架生成

- 按 templates/skill-skeleton.md 出：SKILL.md + references（按需，首版每件都进索引）+ scripts（有数字纪律能机检的必须配）+ 变更.md（首条=建包记录+验收清单）。
- 文件名 kebab-case；name=目录名。

## 第9步 自检闭环（不过不算交付）

1. `node scripts/skill-audit.js <新目录>` → FAIL 清零。
2. 九维语义自评（audit-rubric.md），新 skill 首版 ≥75 才交付；<75 回炉弱项。
3. 验收清单逐条跑（变更.md 里的清单），结果回填。
4. 实战首跑后：踩的坑当场追加新 skill 的 lessons-ledger（骨架里带空账本文件）。
