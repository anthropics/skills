# 八条模式（宪法·源自 skillhub TOP5000 过滤后的幸存者共性）

> 来源：2026-11-04 爬取 skillhub.cn TOP5000（按分数），漏斗过滤（仿品/光杆/无效果宣称/换皮）后深读 30 个头部 skill 提炼。八条是「过滤完全场后活下来的技能反复在做的事」。安检评分、生成设计、升级目标全部锚定这八条。

每条＝定义｜为什么｜可检判据（机检=skill-audit.js 管；人检=agent 对照证据审）｜典型反例。

## ① SKILL.md 只当路由器

正文留「任务→读哪个文件」索引表，细节下沉 references，配三层阅读路径（速查→正文→references，读完速查能上手80%）。
为什么：SKILL.md 每次会话全文进上下文，正文肥=每次都付 token 税；细节按需加载才省。
判据：机检——SKILL.md ≤15KB、无孤儿文件、引用文件全存在；人检——有「何时读哪个文件」的索引表、三层路径存在、references 单文件职责单一。
反例：正文塞全量手册（某头部 skill 47KB 正文），或 references 文件存在但正文从不指路（agent 永远读不到）。

## ② 纪律全部数字化（可触线）

「尽量/注意/适当」改写成「数字上限＋到顶后动作」，agent 能自检是否触线。
为什么：模糊规则等于没有规则——「澄清至多2轮，第3轮起用默认假设继续」可执行，「尽量少问」不可执行（高质量skill设计指南实证）。
判据：机检——模糊纪律词所在行无数字=警；人检——重试/回退/澄清/加载/探索类纪律每条都有上限+到顶动作。
元纪律：写不出数字上限的纪律不许写进 skill。
反例：「注意性能」「避免太长」。

## ③ 关卡式工作流

流程不是直线是门：确认门（强制暂停等人拍板）、质检门（不过不许发出）、付费/危险动作门。
为什么：把 agent 自由度关进可枚举的关卡，是防跑偏的主流解法（付费skill三时机话术、exit 2 不许发布、5方向用户选）。
判据：人检——至少标出哪些步骤必须人拍板；产出物有质检门且「不过的后果」写明（回炉/不发/中止）。
反例：一口气从头跑到尾，中间无暂停点。

## ④ 诚实状态是一等公民

不知道/未运行/推断 都是合法输出状态，带标签：[已验证]/[推断]/[待核实]、五态判定（把「网络故障」和「查无」分开）、弱归因标注、「未运行就写未运行」。
为什么：不装懂的 skill 评审分显著更高；误报比缺报危害大（PMID验证：绝不误报「不存在」）。
判据：人检——输出里有没有证据标签机制；失败/缺口是否显式标注而非静默；拿不准是否取低一级结论。
反例：静默降级、失败装成功、编造结果填空。

## ⑤ 机器管客观、模型管语义

可复现检查全走脚本（计数/校验/对账），报告由脚本生成禁手写；语义判断（好不好/顺不顺）才归模型。
为什么：写表的和查表的不是同一个脑子才可信；脚本可回归，模型自查会漂（鲁班：同源自评×0.5）。
判据：机检——scripts/ 存在且语法过；人检——数字纪律有没有对应机检脚本、自检是不是证据制（贴数字贴原文，不许空口打勾）。
反例：自检清单全是「□ 已达标」空勾。

## ⑥ 失败经验资产化

误报台账、编号坑清单（递增带日期）、反模式档案、拒绝账本——只写 happy path 的都被过滤掉了。
为什么：现场教训不落盘，同一个坑每场对话重踩一遍；坑账本是 append-only 才有效。
判据：人检——有没有 lessons-ledger/FAQ/坑清单且带编号和日期；新坑有没有回写动作写进流程。
反例：FAQ 是某个版本的静态快照，之后从没更新过。

## ⑦ 交接全协议化

退出码表配话术（每个码=什么状态+用户说什么）、stdout 标记块给 agent 机读、幂等键防重复动作。
为什么：skill 与脚本、skill 与 skill 的边界协议化后，失败可编排、可续跑、不重复扣费（===POINTS_USED=== 标记块、402属正常流程）。
判据：人检——脚本退出码语义是否有表；跨步交接是否有固定字段/标记块；重复执行是否幂等。
反例：脚本失败只打一行日志，agent 不知道该重试还是放弃。

## ⑧ 预期管理前置

用/别用双向触发表、负面承诺清单（不做什么、不承诺什么）、可信承诺=设计目标+不承诺X+可验证指标。
为什么：裸担保（"100%过审"）在头部 skill 里已被删掉并留档（论文润色skill 自我纠错史）；预期错配是差评主源。
判据：机检——description 有排除区；人检——有没有「不做」清单、承诺是否可验证、有没有「不承诺X」声明。
反例：description 只写能干什么，触发后什么活都接。
