# 升级循环（鲁班棘轮·单变量·独立评分）

> 依据：鲁班.skill 循环机制裁剪到本机可跑（不依赖其 TSV 工具链，产物改用 md 台账）。目标=在不动功能语义的前提下提升 skill 工程质量；**功能/逻辑改动走 change-guard，不进本循环**。

## 硬规则（违反任一=整轮回滚）

1. 每轮只改一个维度（改其一时观察相邻维：路由化/数字化/机器可检三者联动）。
2. 单轮字符变化 ≤10%；SKILL.md 总大小 ≤ 原来的150%。
3. 编辑前备份（目标目录 cp 整目录为 `<名>.backup-pre-升级`，或 git commit）。
4. 评分独立性：评分必须开子agent（独立上下文）按 audit-rubric.md 打分；编辑与评分同源 → 涉及维 ×0.5。
5. 棘轮：新分>旧分才保留；否则回滚本轮 + 记拒绝账本。
6. 振荡守卫：同一维度 A→B→A 来回改的，记入振荡名单跳过，不再轮。
7. 循环 ≤5 轮；连续 2 轮 Δ<0.5 分（百分制）=触顶，停下来问用户：加1轮／弱项重写／收工。

## 流程

**Phase 0 基线**
1. `node scripts/skill-audit.js <目录>`（机检FAIL先修完才进循环）。
2. 子agent 九维评分（audit-rubric.md）→ 基线报告存目标目录 `upgrade-baseline.md`。
3. 弱点排序：修哪个性价比最高 = 权重×(5-维度分) 降序。

**Phase 1 循环（≤5轮）**
1. 选最弱未振荡维度 → 提 1 个具体方案（先查拒绝账本防重提 + 反例黑名单对照）。
2. 备份 → 编辑（单维、≤10%）。
3. 子agent 重评该维+联动维。
4. 棘轮判定：总分升 → 保留，写优化台账；不升 → 回滚，记拒绝账本。

**Phase 2 收口**
- 复跑机检 + 九维 → 对比基线报告，前后分写进目标 skill 的 变更.md。
- 可复用规律（跨skill通用的）追加进本skill的 references/lessons-ledger.md。

## 产物（都放目标 skill 目录）

| 文件 | 内容 | 规则 |
|------|------|------|
| upgrade-baseline.md | 基线九维分+证据 | 升级开始时写，之后不改 |
| rejected-edits.md | 拒绝账本：目标维度/改动段落/方案摘要/拒因/绕行建议 | append-only |
| upgrade-registry.md | 每轮：轮次/维度/前分/后分/去留 | append-only |

## 反例黑名单（提方案前对照）

1. 一轮改多个维度（无法归因）
2. 靠加字数提分（堆解释、堆触发词、复制粘贴reference进正文）
3. 自评自改同一上下文闭环
4. 「重构」名义动功能语义
5. 删证据制自检来「变简洁」
6. 删坑账本/FAQ 来「变干净」
7. 触发词越加越多不换血（description 超限风险）
8. 弱项绕着走只修容易的
