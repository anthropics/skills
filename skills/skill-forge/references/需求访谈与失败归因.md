# 需求访谈 & 失败归因（两个「把人话接进来」的关口）

## 一、为什么录制完必须问人

录一遍「加预算」，只能得到「点哪几下」。用户实际要的是：
**什么时候加、加多少、加到哪个账号、超了谁批、跑完给谁、失败了找谁。**

这些录制看不出来。不问，产物就只是「把人工重复一遍」，不是自动化。
（2026-11-06 用户原话：「这样子没有动作的规则，你做出来最多是一个重复的路径而已」。）

**但反过来也不行**：拿一张固定表格硬卡人，业务场景千变万化（下载表→粘在线表格、加预算看阈值、日报看定时），
卡死的模板会把人挡在门外。所以口径是 **只问、不固化**（2026-11-06 用户定）：

- 答不上来 / 答得糊 → 记进 `待确认`，**不拦着生成**；
- 这份「欠账」会一路写进子技能 SKILL.md 的「还欠确认」段，谁接手都看得见；
- 想强制问全再生成，才加 `--strict`（默认不强制）。

## 二、怎么问

```bash
# 交互（人在场，一条条问；不知道直接回车 = 记待确认）
node scripts/interview.mjs --link 加预算 --type api

# 非交互（agent 已经问过、或批量跑）
node scripts/interview.mjs --link 加预算 --answers answers.json --out produced/加预算/配置

# 强制问全（不给「待确认」留口子）
node scripts/interview.mjs --link 加预算 --answers answers.json --strict
```

落盘：`<config>/触发.json`；同时打印「## 什么时候跑」段（`build_skill` 会自动写进子技能 SKILL.md）。
生成时建议带 `--require-trigger`（完全没问过就拒绝）；不带则在子技能顶部插「⚠️ 还没问过需求」待办。

### 问哪几项（问了不等于必须马上答）

| 项 | 问它是为了什么 | 答不上来时 |
|---|---|---|
| 用途 | 一次性 / 定时 / 事件触发 / 人工按需 —— 决定它能不能无人值守 | 记「待确认」，先按人工按需对待 |
| 触发 | cron 表达式；或「指标 + 阈值 + 多久查一次 + 一次最多动多少 + 超限谁批」 | 记「待确认」；写操作场景提醒「先别自动跑」 |
| 参数从哪来 | 重放时每个变量填什么（固定值 / 人工给 / 上级表读） | 记「待确认」 |
| **产出形态**（可多选） | 本地文件 / 在线表格 / 接口回填 / 页面回读 / 只给人看 | 记「待确认」 |
| 落在哪、给谁 | 具体路径或表名 + 接收方 | 记「待确认」 |
| 怎么算成功 | 行数下限 / 回执号 / 页面提示 / 字段数 | 记「待确认」 |
| 失败找谁 | 谁看、重试几次、怎么通知 | 记「待确认」 |
| 会不会改数据 | 写操作要上限 + 谁批 + 先 DryRun | 记「待确认」，跑前先问一句 |

### 三种画像（用户 2026-11-06 点名的两类 + 一次性）

- **事件触发**（例：消耗到日预算 90% 加 100 元）
  → 要问：监控指标、阈值、检查频率、**单次/日累计上限**、超限谁批。
  没上限的事件触发 = 无限自动执行，`triggerSection` 里会单独提示「别做成无限自动执行」。
- **定时**（例：每天 9 点下载昨天数据写日报）
  → 要问：cron（5 段）+ 数据日期口径（昨天是按自然日还是投放日）。
- **一次性** → 标 `once`，不生成定时，跑完即结束（别硬做成定时任务）。

### 产出形态认这几种（可多选，别只认「落本地文件」）

| 形态 | 典型链路 | 谁负责 |
|---|---|---|
| 本地文件 | 导出 csv/xlsx 到 `data/` | `api_run --out` / UI 版下载 |
| **在线表格** | 下载表格 → 打开 tab → 粘贴到在线表 | 映射**自动对列头**（下载表列头 ↔ 目标表列头，`analyze.py` / `tableread.mjs`），人只核对一眼；详见 `UI版-表格搬运.md` |
| 接口回填 | 直接调接口写回 | `api_run --go` |
| 页面回读 | 贴完再回读核对 | UI 版回读步骤 |
| 只给人看 | 不落盘，跑完截图/清单给人 | 人工 |

> 选「在线表格」时 `触发.json` 会自动带一条 `产出.映射`：**列头自动对，不用人手写映射表**。
> 这就是用户说的「他打开了 tab 粘贴到在线表格，那映射关系就出来了」。

## 三、浏览器之外：本地文件看不看得到？

看得到，但要分清两件事：

1. **不能读「已经打开的 Excel 窗口」** —— CDP 只管浏览器，读不了别的程序的窗口内容。
2. **能读文件本身**，也能把人叫来看：

```bash
# 读下载下来的表：行数、列名、前几行（xlsx 用标准库解 zip+xml，零第三方依赖）
python scripts/localview.py --file downloads/投放数据.xlsx
python scripts/localview.py --file data/日报_20261105.csv --rows 10

# 找「刚下载的那份」：按修改时间列目录最新几个
python scripts/localview.py --dir "C:/Users/<你>/Downloads" --latest 3

# 直接调系统默认程序打开给人看（Excel/WPS/记事本）
python scripts/localview.py --file downloads/投放数据.xlsx --open
```

用途：跑完不靠人猜「表到底下到没有、里面是不是我要的数据」——行数、列名、样例行直接打出来；
接「在线表格」形态时，正好拿这份列头去对目标表列头。

## 四、失败用人话（diagnose）

用户不该看到 `exit 3`。归因规则只有一份：`scripts/lib/diagnose.mjs`，
两个入口共用：`scripts/diagnose.mjs`（命令行）、`scripts/manage.mjs fail`（记账时自动归因）。

```bash
node scripts/diagnose.mjs --http 401
node scripts/diagnose.mjs --err "Timeout waiting for selector .export-btn" --exit 3
node scripts/manage.mjs fail --link 加预算 --phenomenon "接口 401" --http 401
```

输出固定五句：**现象 / 人话 / 哪坏了 / 下一步 / 要不要重录**（+ 归因码）。

| 归因码 | 现象 | 人话 | 要不要重录 |
|---|---|---|---|
| CAPTCHA | 验证码/滑块 | 得你手动登一次 | 不要（重录也没用） |
| LOGIN | 401/403/token 过期 | 登录过期，重登一次 | 不要 |
| RATE | 429/限流 | 跑太快，等会儿再跑 | 不要 |
| SEL | 元素找不到 / exit 3 | 按钮没了，多半网站改版 | **要** |
| FIELDS | 字段数对不上 | 回来的列变了 | 字段变少/改名才要 |
| EMPTY | 行数 0 | 先看日期/账号参数 | 参数对还没数据才考虑 |
| TIMEOUT | 超时 | 网络或站点慢，重跑一次 | 连续 3 次才考虑 |
| SERVER | 5xx | 网站自己出错 | 不要 |
| FS | ENOENT/EACCES | 文件正开着或没权限 | 不要 |

认不出来时**不许硬猜**：输出「认不出来 + 该补哪三条信息」。乱归因比不归因更坏。
