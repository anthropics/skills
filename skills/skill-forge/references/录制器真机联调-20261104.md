# 录制器真机联调：三个「录出来永远 0 条」的硬 bug（2026-11-04）

> 背景：技能自测（`test/run_offline_test.py` 7/7、`test/run_node_test.mjs` 9/9）全过，但真机一跑就是 0 条。
> 单元测试用的是**手写的 fixture rec.json**，完全绕过录制链路，所以测不出来。

## 症状

`record.mjs` 起浏览器 → 用户在窗口里跳页/点击 → 录完，rec.json 里 `counts.total = 0`，
控制台没有任何报错，进程「正常完成」。

## 三个根因（都在 record.mjs / lib/cdp.mjs，已修）

| # | 代码 | 后果 | 修法 |
|---|---|---|---|
| 1 | `if (!window.__SOP.recording) { __SOP_start(); }` | recorder.js 的状态位叫 **`S.on`**，`__SOP.recording` 永远 undefined → 每轮轮询都 `__SOP_start()` 一次，**动作刚记就被清空** | 改判 `window.__SOP.on` |
| 2 | `injectFile()` 走 `evalJs()`，而 evalJs 会给表达式再包一层 IIFE | recorder.js 以 `/* 注释` 开头、以 `})();` 结尾，包完就是**语法错误**；异常被 `.catch(() => {})` 吞掉 → 跳页后注入静默失败 | `injectFile` 直接 `Runtime.evaluate` 原文，有 `exceptionDetails` 就抛 |
| 3 | `send()` 无超时、`ws.onclose` 没处理 | 整页跳转/关标签时连接断，Promise 永久 pending → 轮询卡死，**之后整场不再录**（进程还活着、日志不再更新） | `send(method, params, timeoutMs=15000)` + `onclose` reject 全部 pending + 失败后重连 `Cdp.attach` |

附带改动：
- 轮询间隔 1500ms → **500ms**（跳页瞬间丢的动作从 1.5 秒降到 0.5 秒）。
- 新增 `followNewTab()`：每轮扫 `http://127.0.0.1:<port>/json/list`，发现新 page target 就切过去并打印 `↪ 跟随新标签`。**用户把地址粘到新 tab 打开也能录。**
- 注入失败不再静默：`console.warn('(注入失败：…)')`，5 秒限频。

## 验证判据（三条全过才算录通）

```js
// 1) 页面上是否注入成功且处于录制态
'JSON.stringify({url:location.href, has:!!window.__SOP, on:window.__SOP?window.__SOP.on:null})'
// 期望 {"has":true,"on":true}

// 2) 真实鼠标点击（合成 el.click() 未必被记），用 CDP 派发
Input.dispatchMouseEvent { type:'mousePressed',  x, y, button:'left', clickCount:1 }
Input.dispatchMouseEvent { type:'mouseReleased', x, y, button:'left', clickCount:1 }
// 等 1.5s： JSON.parse(__SOP_dump()).actions.length  期望 > 0

// 3) 让 --minutes 1 自然收尾（进程 kill 不会触发收尾逻辑，文件不落盘）
//    看控制台「动作 N 条」== rec.json 里的 counts.total
```

只看进程退出码 / 日志「录制完成」不算验过。

## 已知边界

- 跳页瞬间 0.5 秒窗口内的动作会丢（点完立刻整页跳转的那一下可能记不到）；真实链路「点导出 → 下载」不跳页，不受影响。
- `followNewTab` 只切到「最新出现的 page」，同一场开多个业务 tab 交叉操作会漏。
- `chrome_profile/` 建在技能根目录（登录态），**打包给同事时必须排除**，否则带走本机登录数据。

## 排查顺序（下次遇到「录不到」照着走）

1. 页面上 `!!window.__SOP` → 不在 = 注入问题（看 console.warn）
2. `window.__SOP.on` 是否 true → 不是 = 状态位 / start 问题
3. `__SOP_dump().actions.length` 一直是 0 而 on=true → 事件没绑上，或被反复 start 清空
4. 进程 uptime 在涨但日志停住 → CDP 请求挂死（超时/断线兜底）
