## 1 失败自愈（对应 `scripts/lib/heal.mjs` + `run.mjs`）

### 为什么
6 级定位（L1 id → L6 nth-path）录制时就存了，但以前回放只用 `best定位`；一失效就整个失败。
网站小改版（按钮换 class、外面多包一层 div）时，其它级别往往还能点到同一个元素——不是真要重录。

### 怎么跑
```bash
node scripts/run.mjs --config 配置 --go            # 只报告，不动定位库
node scripts/run.mjs --config 配置 --go --heal     # 命中的新定位回写 定位库.csv
```

逐级顺序（固定，不许改）：
`best定位 → L1_id → L2_testid → L3_role → L4_text → L5_css → L6_nth_path`

### 判定口径
| 情况 | 结论 |
|---|---|
| 原定位点到了 | 正常，不打印自愈 |
| 第 2~7 个候选点到了 | 自愈成功：打印 `[自愈] 第N步…用 <级别> 点到`，写 `logs/自愈.log` |
| 全部候选都点不到 | 才判定「页面失败」→ 引导 `manage.mjs fail` 归因（真改版 / 登录掉 / 验证码） |

### 边界（重要）
- 默认**不回写**。回写会改定位库，属于「改用户资产」，必须显式 `--heal`。
- 回写只改命中的那一步（`applyHeal` 按 `步骤` 精确匹配），找不到对应步骤就 `changed=0`，绝不瞎改。
- 记录分两处：`配置/自愈记录.csv`（跟子包走，方便接手人看到哪步被修过）+ `logs/自愈.log`（工厂侧汇总，`manage.mjs heal` 读它）。
- **同一链路自愈频繁** = 网站正在改版期 → 看 `manage.mjs heal`，3 次以上考虑整条重录升级。

### 代码入口
- `levelCandidates(step)`：生成候选（原定位在最前，空值/重复自动跳过）
- `attemptJs(sel, act, value)`：生成 CDP 里「找到并操作」的 JS
- `firstHit(cands, run)`：async 逐级试，返回 `{hit, misses, tried}`
- `applyHeal(csvText, step, newSel)`：纯函数改 CSV 文本，返回 `{text, changed}`
- `healRecord(...)` / `healLogLine(rec)`：统一记录格式

## 2 元素快照（对应 `assets/recorder.js` 的 `collectLocators`）

录制每个动作时，除定位串再存：

```json
"snapshot": {
  "tag": "BUTTON", "role": "button", "name": "确定",
  "html": "<button class=\"btn-primary\" data-v-3f2a>确定</button>",
  "attrs": { "id": "", "class": "btn-primary", "type": "button" },
  "rect": [820, 640, 88, 32]
}
```

口径：
- `html` **只取前 300 字**（`slice(0,300)`），防止录制文件膨胀；
- 不存整页 HTML、不存 cookie/localStorage、不存输入框里已有的业务值；
- 用途：改版后回答「当时那个按钮长什么样、在页面哪个位置」，重录时不用靠人回忆。

## 3 单遍判参（对应 `scripts/lib/infer.mjs` + `scripts/infer_params.mjs`）

### 为什么
以前只有「同一操作录两遍比 diff」才知道哪个值是变量，成本翻倍。多数值其实一眼能判。

### 启发式（按命中顺序，命中即停）
| 线索 | 判定 | 置信度 |
|---|---|---|
| 值是日期格式（`2026-10-30` / `2026/10/30` / `10月30日` / `20261030`）且字段名像日期 | 变量（日期） | 0.90 |
| 值出现在本次录制的某个接口响应里 | 变量（接口带出） | 0.85 |
| 值出现在页面 URL 的 query/path 里 | 变量（页面带出） | 0.80 |
| 长数字 ≥ 8 位，或字母数字混合且 ≥ 10 位 | 变量（单号/ID） | 0.75 |
| 字段名含 预算/金额/出价/数量/上限，且值是数字 | 变量（数值） | 0.70 |
| 其余 | 常量 / 待确认 | 0.40 |

### 用法
```bash
node scripts/infer_params.mjs --rec recordings/xxx.rec.json
node scripts/infer_params.mjs --rec recordings/xxx.rec.json --out 参数判定.csv
node scripts/infer_params.mjs --rec recordings/xxx.rec.json --json
```

### 边界（别把提示当规律）
- 输出固定带一句「这是提示，不是定论」；
- 关键链路（钱/提交/对外发布）**必须**两遍 diff 复核；
- 纯点击链路直接说「没有填值步骤」，不硬编结论。

## 4 口述备注（`assets/recorder.js` 浮标 + `record.mjs` + `interview.mjs`）

### 为什么
录制只能录「点了什么」，录不到「为什么这时候加」。用户原话：「只有加的动作，不知道什么时候加」。
录完再问，人往往已经想不起来当时为什么这么点。

### 怎么用
1. 录制中，浮标里「说一句：这步为什么这么做」→ 回车或点「记下」；
2. 存进 `rec.json.notes`：`{ seq: 当时动作数, at: 时间, text: 原话 }`；
3. 访谈时带 `--rec`：
   ```bash
   node scripts/interview.mjs --link 加预算 --rec recordings/加预算.rec.json
   ```
   会把原话打出来，并写进 `触发.json` 的 `录制备注` + `录制备注提示`；
4. 生成子包时，说明书「九、录制时你自己说的话」原样保留。

### 边界
- 备注**不算一次操作**：不进 `actions`、不进定位库、不影响动作序号；
- 备注 ≠ 答案：跟访谈答案冲突时，以答案为准（答案是事后想清楚的）；
- 备注只落本机 `recordings/*.rec.json`，随子包交付时才随 `触发.json` 走，脱敏规则同其它产物。
