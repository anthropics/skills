# 浏览器之外的「看结果」：localview.py 怎么用、xlsx 怎么零依赖读

链路跑完，人第一句问的通常是「表下到哪了？里面是不是我要的数据？」。
CDP 只管浏览器，读不了别人程序的窗口；能做的两件事：**读文件本身**、**把文件调起来给人看**。

## 一、命令

```bash
python scripts/localview.py --file downloads/投放数据.xlsx          # 行数 / 列名 / 样例行
python scripts/localview.py --file data/日报_20261105.csv --rows 10
python scripts/localview.py --dir "…/Downloads" --latest 3          # 找刚下载的那份
python scripts/localview.py --file x.xlsx --open                    # 调系统默认程序打开
```

退出码：`0` 正常｜`4` 文件不存在/不支持的类型。**读不到就说读不到**，不许拿空结果糊弄成「表是空的」。

## 二、xlsx 零依赖解析（本机没有 openpyxl / Excel 时）

xlsx 就是个 zip：`xl/workbook.xml`（表名）、`xl/sharedStrings.xml`（文本池）、`xl/worksheets/sheetN.xml`（单元格）。
用标准库 `zipfile` + `xml.etree` 就够，别为读一张表去装包。

### 必须按「本地名」匹配标签，否则静默 0 行

```python
def L(tag):            # '{ns}row' → 'row'
    return tag.rsplit('}', 1)[-1]

for el in root.iter():
    if L(el.tag) == 'row':
        ...
```

**坑（2026-11-06 实测）**：直接写 `root.iter('{ns}row')` 或 `'m:row'`，遇到**没有命名空间**的手工/第三方导出 xlsx（本次 `test/_fixture/mini.xlsx` 就是）
会一条都匹配不上，结果是「工作表 1 行 0 列」——不报错，看着像那表真的是空的。判据：**文件明明有内容却读出 0 行 = 命名空间匹配错了**。

### 单元格取值的三条分支

| 情况 | 读法 |
|---|---|
| `t="s"` | `<v>` 里是 sharedStrings 的下标 → 查池子 |
| `t="inlineStr"` / 富文本 | 取 `<is>` 下**所有** `<t>` 拼接（可能是多段 run） |
| 其它（数字/日期序列号） | 直接用 `<v>` 原文；日期别自作聪明转格式，原样给人看 |

sharedStrings 池：遍历所有 `si` 节点，把其中每个 `t` 的文本连起来（一个 si 可能被拆成多段 run，只取第一个 `t` 会缺字）。

### 列对齐要看 cell 的 `r` 属性

空单元格在 XML 里**不出现**。只按子节点顺序 push 会让后面所有列左移。
按 `r="C5"` 里的字母算出列号（`A=0, B=1 … Z=25, AA=26`），空位补 `''`。

## 三、其它格式

- **csv/tsv**：用 `csv.reader` 而非 `split(',')`（引号里带逗号的行会散架）；编码按 `utf-8-sig` → `gbk` 依次试，别默认 UTF-8（Excel 另存的是 GBK/BOM）。
- **json**：只打顶层键和条数，别整份 dump（大文件会淹没上下文）。
- **Excel 打开 csv 乱码**：那是「给人看的 csv 要不要带 BOM」的问题，口径见 `windows-powershell-gitbash-scripting` §二。

## 四、接「在线表格」产出形态时

`触发.json` 里 `产出.形态` 含「在线表格」时，`产出.映射` 写的是「列头自动对」：
拿本脚本读出的**下载表列头**，去对目标在线表的列头（`analyze.py` / `tableread.mjs`），
人工只核对一眼，不用手画映射表 —— 这就是「他打开 tab 粘贴，映射关系就出来了」这句话的落地方式。
