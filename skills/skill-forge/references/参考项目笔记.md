# 参考项目笔记（2026-10-31 调研：做 skill-forge 前看过什么、各借了什么）

## 一句话结论

市面上分两派：**AI 实时驾驶派**（千问 BrowserQwen、Kimi 浏览器插件、browser-use、Skyvern、Stagehand——LLM 每步现看页面现决策）和**录制回放派**（Chrome DevTools Recorder、Selenium IDE、影刀 RPA——录一次定格式，之后确定性重放）。

我们要的是**搬运的绝对准确**，所以主干走录制回放派，只借 AI 派的自愈思想：

| 项目 | 是什么 | 借了什么 |
|---|---|---|
| 千问 BrowserQwen（Qwen-Agent 官方扩展） | 浏览器扩展 + 工作站，AI 看当前页内容问答 | 不借架构（它是"陪伴看页"，不管数据搬运安检） |
| Kimi 浏览器插件 | AI Agent 驱动浏览器开页/点击/填表 | 借"用户操作一次、AI 在场观察"的入口体验——record.mjs 的注入观察是同思路，但不装扩展（CDP 注入零安装） |
| browser-use | Python，DOM 优先，LLM 每步决策 | 借**自愈定位**：选择器挂了按语义再找——act.js 的六级降级链（#id→testid→role→文本→css） |
| Skyvern | 视觉+DOM 混合，工作流可参数化 | 借**参数位**思想：账户/日期/渠道全是参数不写死 → 路由表.csv + 参数位.md |
| Stagehand（Browserbase） | Playwright 之上加 act/extract/observe 原语 | 借**动作词表收敛**：run.mjs 只有 click/fill/select/download/paste 几个动作 |
| Chrome DevTools Recorder | 浏览器自带录制，导出 Puppeteer/Playwright JSON | 印证"录→JSON步骤→回放"模型；作者前代项目的 run.json 同构，格式不换 |
| Selenium IDE | 老牌录制回放，locator 回退链 | 多级 locator 回脱是其 20 年老结论，六级定位照此 |
| 影刀 RPA（商业） | 指令卡 + 元素库 | 借**元素库=数据文件**：定位库.csv，改版只改表不改脚本 |

## 不走 AI 实时驾驶的原因（记录备查）

每步都过 LLM = 每步都可能不确定 + 慢 + 费 token；数据搬运错一格就是事故。所以本工厂：**执行 100% 确定性（配置+定位库），AI 只出现在建造和修的时候**（录完分析、失败升级）。这也正是作者前几个取数项目的历史结论——取数走接口、口径落字典，比"让 AI 每次现场看页面"稳。
