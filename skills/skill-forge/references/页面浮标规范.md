# 页面浮标（HUD）规范：让"跑起来的自动化"看得见

> 用户要求（2026-11-06 / 11-10 两次）：自动化跑起来要能在页面上看见「在不在跑 / 跑到哪 / 刚做了什么」，能就地暂停、结束；
> 录制器还要能「点开始才录、点停止就停」、「点错了撤销」、「给每一步写这步是干什么 / 什么规则」。
> 参考样式来自「投放后台·批量建单元」面板。凡是要连续跑一段时间、又要人盯着放心的链路（录制器、批量建单元、批量回填），都照这份做。

## 版式（照着抄结构，别自由发挥）

```
┌──────────────────────────────────────────┐
│ ● 网页操作录制 · 链路名            [收起]  │  ← 红点闪烁=在录，橙=暂停，绿=已停
│ 正在录制…                                 │  ← 状态行（蓝=录 / 灰=待机 / 橙=暂停 / 绿=已停）
│ 动作 12 · 点击 5 · 填充 2 · 粘贴 1 · 备注 3 │  ← 计数行（权威数由驱动推）
│ 刚记录：✎ 填写「2026-11-06」               │  ← 最近一条
│ ┌──────────────────────────────────────┐ │
│ │ 这步是干什么 / 规则（如：预算到 80% 就改 200）│ │  ← 每步备注输入框
│ └──────────────────────────────────────┘ │
│ [          开始录制 / 停止录制          ] │  ← 大按钮：待机=橙「开始录制」，录制中=红「停止录制」
│ [   暂停   ] [      撤销上一步      ]     │  ← 次要操作
│ ┌──────────────────────────────────────┐ │
│ │ [17:44:16] ▶ 导出报表                  │ │  ← 流水日志（≤40 行，自动滚到底）
│ │ [17:44:16] ✎ 填写「2026-11-06」  ★备注  │ │
│ └──────────────────────────────────────┘ │
└──────────────────────────────────────────┘
```

- 尺寸 340px 宽、白底、圆角 12、阴影 `0 14px 34px rgba(0,0,0,.22)`，固定右上角 `top:14px; right:14px`。
- **大按钮语义 = 用户点的那一下**：待机「开始录制」→ 点完文字变「停止录制」→ 再点就停（并置 `stopReq`）。不再用「自动开录 + 暂停/结束两个按钮」。
- 「收起」进迷你态：只剩一行标题，不挡页面。
- 日志每行带 `data-seq`，点某行 = 选中那一步，随后写的备注挂到它上面（默认挂最后一步）。

## 实现要点（八个都是踩过的）

1. **Shadow DOM 隔离**：`host.attachShadow({mode:'open'})`，样式写在 shadow 内的 `<style>`。站点 CSS 再野也改不了浮标，浮标也不会污染站点。
   host 本身 `position:fixed;top:0;left:0;width:0;height:0;z-index:2147483647`，卡片在 shadow 内自己 fixed。
2. **点浮标不能算操作**：`document` 上的 capture 监听先于 shadow 内按钮的 click 触发，所以监听器里必须先判
   `e.composedPath().indexOf(host) >= 0`（或 `e.target === host`）→ 直接 return。否则每次点开始/停止都会多录一条假点击。
3. **待机态不许自动录**：注入后 `armed=false`、`on=false`，只显示面板不记动作。驱动侧原来那句 `if (!on) start()` 会立刻把待机冲掉，
   改成 `if (armed && !on && !pausedByUser && !stopReq) start()`——换页重新注入时驱动先 `__SOP_arm(true)` 再 start，状态不断。
4. **暂停要能真停**：页面上有 `pausedByUser` 位，驱动 `!pausedByUser` 才自动拉起，否则每 0.5 秒就把暂停冲掉、还会清空已录动作。
5. **计数以驱动为准**：页面自己只做即时反馈（自己 push 时刷新一次），驱动每轮把**跨页/跨 tab 的总数**推回来覆盖，避免换页后数字归零。
6. **停止按钮 = 收尾信号**：页面只置 `stopReq=true`，由驱动检测到后存盘 → 后续处理 → 按端口关浏览器。页面不要自己去做收尾。
7. **备注要挂到具体那一步**（用户 11-10 要求）：`action.note` 存「这步干什么 / 规则」，不要只丢进全局 notes。
   后面 `record.mjs` 打步骤清单、`evidence.mjs` 时间线、`interview.mjs` 预填规则都直接读它，能少问一大截。
   一条动作都没有时，备注退化成全局规则（`notes`）。
8. **图标用符号不用 emoji**：`▶ ✎ ▤ ⧉ ⬇ ▾ ✔ ⬆ → ⇄ ↩ 💬`。emoji 在无 emoji 字体的环境是豆腐块。

## 接口契约（页面 ↔ 驱动）

```js
// 页面暴露
window.__SOP_hudSet({ name, actions, net, status })   // 驱动每轮推；name 首次传入时建浮标
window.__SOP_hudState()                               // → {stop, on, paused, armed, actions, noteTarget}
window.__SOP_start()                                  // 开录（清空动作，armed=true）
window.__SOP_arm(true)                                // 只置 armed，不清动作（换页重新注入时用）
window.__SOP_undo()                                   // 撤销最后一步，返回被撤销的 seq
window.__SOP_addNote('文字')                          // 备注挂当前选中步 / 最后一步
window.__SOP_drop([3,4])                              // 就地剔除误点（驱动侧另有 manage.mjs drop）

// 驱动侧（每轮）
const hud = JSON.parse(await cdp.evalJs('__SOP_hudState()'));
if (hud.armed) started = true;                        // 用户点过开始
if (hud.stop) { sessionEnd = true; }                  // 用户点了停止录制
await cdp.evalJs(`__SOP_hudSet(${JSON.stringify({ actions: merged.size, net: reqs.length })})`);
```

> 注意：`cdp.evalJs(expr)` **不要**传 `{awaitPromise:false}` 去取值，否则拿到的是 `{}`（Promise 被序列化成空对象）。

## 多标签 / 多页面

- 每个 http(s) 标签单独一条 CDP 会话、各自注入；**新开标签自动接上**（`/json/list` 每 400ms 同步一次，关掉的自动摘掉）。
- about:blank / chrome:// 不接——避免把空白页和新标签页当业务页面。
- 录制中用户点链接/按钮弹出新标签时，新标签的浮标状态直接是「正在录制…」，动作照记。
- 收尾按真实时间（`at` 的 HH:MM:SS）重排、统一重编号；`--drop` 序号按重排后的新序号。
- 后台标签会被 Chrome 推迟解析（`readyState=loading`）：驱动检测到就**先不注入**，等解析完再挂浮标；测试里新开标签要 `/json/activate` 切前台。

## 验证方法（不靠肉眼看）

1. headless Chrome（`mode:'bg'`）+ **profile 放 `os.tmpdir()`**（放技能目录会污染打包后的脱敏自查）。
   **坑**：上次没退干净的实例仍占着同一个 profile 时，新进程连上去 `Page.enable` 会 15s 超时（表象是 SKIP）。
   处理：先按端口关（`closeChromeByPort(18898)`）+ 删掉 `%TEMP%/sf_hud_profile`，再重跑。
2. 注入页面脚本 → `__SOP_hudSet({name})` → 断言待机：状态含「待机」、大按钮文字 =「开始录制」、`armed=false`。
3. 点大按钮 → 断言文字变「停止录制」、状态含「正在录制」、`armed=true`。
4. 真点一个按钮 + 填一个输入框 → 计数行含「点击 1」「填充 1」；日志行数 ≥2。
5. 备注框写一句 → 断言最后一步 `action.note` 含这句、计数行含「备注 1」、`actions` 不变。
6. 点「撤销上一步」→ 断言 `actions` 少 1、`stop` 仍为假。
7. 点「暂停」→ 断言 `actions` 没变、`paused=true`、标题含「已暂停」。
8. 点「停止录制」→ 断言 `stop=true` 且 `actions` 仍没变。
9. `Page.captureScreenshot` 出 PNG，用 vision 看一眼有没有豆腐块/错位（这一步真拦住过 emoji 问题）。

现成实现与测试：`assets/recorder.js`（浮标段）+ `test/run_hud_test.mjs`（24 断言，缺 Chrome 则 SKIP 不阻塞）。
