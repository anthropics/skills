# 生命周期：失败记账 → 3 次重录 → 版本与旧包

## 一、失败怎么记

跑不起来 / probe 返回空 → 退出码 3 → 记一笔：

```bash
node scripts/manage.mjs fail --link X --phenomenon "导出按钮找不到" --rootcause "平台改版" --fix "改了 L5 定位"
```

**只记现象和根因，不许写"应该是…"**。查状态：`node scripts/manage.mjs status`。

## 二、升级判据

**同一条链路失败 ≥3 次 → 整条重录**（①→③ 再来一遍）。重录时新动作序列会被 `diffrec` diff 出变化点，正好当升级依据。

- 版本 +1，旧 zip 按周清掉，**台账行永远保留**；
- 真跑通了才许 `node scripts/manage.mjs pass --link X` —— 没跑通记 pass = 台账失真，后面全跟着错。

## 三、旧包口径（用户 2026-10-31 定）

本工厂产物 zip **只留最近 7 天**（`node scripts/manage.mjs clean`，默认 7 天），回滚窗口一周；
`台账.csv` 保留全部版本历史。**其他项目的版本 zip 照旧不删**。

## 四、台账字段（唯一源）

`台账.csv`：`链路,版本,状态,最后变动,zip,失败次数,备注`
- 行只增不删（升级不改写历史行，新版本另起一行）；
- 状态取值：`已生成(api)` / `已生成(ui)` / `跑通` / `失败`；
- 测试脚本跑出来的临时链路不许留在台账里（`test/run_forge_v2_test.mjs` 会自动备份还原）。
