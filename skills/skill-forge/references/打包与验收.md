# 打包与验收（上传平台 / 发给别人装）

## 〇、上传平台的硬约束（违反=包废）

- **平铺无顶层目录**：解压出来直接是 `SKILL.md`、`scripts/`…，不要套一层 `forge/`；
- **路径 ≤3 段**：`test/_fixture/草稿/x.json` 这种 4 段会被拒（2026-11-13 实测：夹具目录提到 `test/` 一层解决）；
- **纯文本**：二进制条目（png/zip/xlsx…）上传时被**静默丢弃**——包里的 zip/xlsx 测试夹具一律不进包，测试现场自己生成；
- **条目名 `/` 分隔**：`shutil.make_archive` 和 PowerShell 5.1 的 `Compress-Archive` 在 Windows 都写 `\`，禁用；`pack_check.py` 手写 `zipfile` 条目。

## 一、打包前排除（跑出来的东西不进包）

`chrome_profile/`（登录态，几十 MB）、`recordings/`、`evidence/`、`produced/`、`logs/`、`test/_out`、`__pycache__`、`*.bak*`、测试现场生成的二进制（`big.zip` / `roundtrip.zip` / `mini.xlsx`）；`台账.csv` 出包时重置为空表头（不带真实链路名）。

## 二、版本与命名

- 版本写 `SKILL.md` frontmatter：`version`（语义化 x.y.z）+ `build: "YYYYMMDDHHMMSS"`，改一次涨一次；
- 包名 `forge-<version>_<md5前5>.zip`，默认落在技能目录的上一级（`--out` 可改）。

## 三、出包 + 验收：一条命令做完

```bash
python scripts/pack_check.py            # 版本读 SKILL.md；--out 改落点；--skip-tests 只出包（不建议）
```

它按顺序做六件事，任一项不过就 exit 1 并点名：干净副本（排运行产物）→ 打平铺 zip → 解压查包里有没有 profile/录制/证据、路径是否 ≤3 段、有没有二进制条目 → 在解压副本真跑五套测试 + 全部 `.mjs` 语法检查 → 脱敏 grep 到 0 命中 → 死文件检查。**要改排除项就改 `pack_check.py` 顶部常量，别每次手写打包脚本。**

手工拆开跑（排查用）：

```bash
node test/run_node_test.mjs        # 9 断言：csv/xlsx/zip/大 zip 回读
node test/run_forge_v2_test.mjs    # 104 断言：diffrec / body 模板 / 字段数 / 写闸门 / login / 需求访谈 / 失败归因
node test/run_hud_test.mjs         # 24 断言：页面浮标（需本机 Chrome，缺则 SKIP）
node test/run_multitab_test.mjs    # 13 断言：多标签录制（需本机 Chrome，缺则 SKIP）
python -I test/run_offline_test.py # 7 断言：UI 版映射链路
node --check scripts/*.mjs test/*.mjs assets/*.mjs
```

**只扫文件清单不算验过**。断言全过才算完成。

## 四、脱敏（对包内容扫，不许对源目录）

`pack_check.py` 内置两条规则，命中即 FAIL：

- **PII**：邮箱 / 11 位手机号（两头加 `\b` 边界，防截中长数字串）/ Windows 用户目录绝对路径；
- **品牌与内部词**：内网品牌、内网项目代号一律不许回流公开包——清单以 `pack_check.py` 顶部的 `BRAND` 正则为准，别在文档里复制粘贴这份清单（文档带字面词自己就会被打红）。

常见漏网点：README 里的示例路径、功能台账的路径表、坑点表里的全路径、代码常量里的本人账号。

三个假命中坑（2026-11-06 / 11-13 连踩）：

1. **二进制被当文本扫**：`*.png` / `*.zip` / `*.xlsx` 用 `errors=ignore` 读进来随机字节会命中规则 → `pack_check.py` 按扩展名跳过；手写 grep 加 `-I`。
2. **代码里写死本人绝对路径**：同时命中用户名规则 → 用环境变量 + `shutil.which` 兜底（见 `pack_check.py` 的 `NODE_CANDIDATES`），别写死盘符路径。
3. **长数字串被手机号规则截中**（13 位毫秒时间戳里可能正好藏着一段形态合格的手机号）：手机号正则必须两头加 `\b` 边界。
4. **扫错对象**：验收测试会在解压目录里现场生成 zip/xlsx——脱敏要扫**包内容**（`ZipFile.read`），不是跑过测试的目录，否则必假阳性。

### 验收跑测试会污染证据目录

`run_hud_test.mjs` 默认截图写 `evidence/`，在解压副本里跑完就把「证据」留在包里、也进了脱敏扫描范围 → `pack_check.py` 跑测试时传 `SF_NO_SHOT=1`，截图函数直接 return；手工跑测试想留图就不设。

**顺序不能换**：先出包 → 再在解压副本跑测试 → 最后对包内容扫脱敏/死文件。对源目录扫等于自己骗自己（源目录本来就有证据和产物）。

## 五、交付口径

回复报：包名 / 大小 / MD5 / 文件数 / 与上版差异。版本链旧包不删不覆盖，回滚点永远是最新那个包。

## 六、版本 zip（本地留档）

每交付一版，当天在工作区根压 `forge-<版本号>-<主题>.zip`（与平台包同内容、同平铺结构），压完开包验证条目名再算交付——这是回滚锚点，不是上传件。
