# prompt-forge：追问成稿

把用户的模糊目标，经过少量高价值追问，变成一份自包含、可直接执行的 agent 提示词。

核心原则：**先问后写**。信息不够硬写，出来的只能是空话。

## 1. 接目标

- 用户带参数（`/prompt-forge xxx`）→ 参数就是目标
- 没参数 → 从最近对话里找；找不到就先问一句"你想做成什么"
- 先用一两句话复述目标，确认没理解歪
- 复述都费劲 = 目标太糊：这一轮只问目标本身，别的别问

## 2. 追问

用 AskUserQuestion 提问（工具不可用就直接文字问）：

- 每轮最多 4 题，每题 2-4 个具体选项，推荐项放第一个、标"(推荐)"，可多选的题开 multiSelect
- 选项要贴用户领域（游戏问玩法平台，文案问受众语气），不出万能套话
- 只问"答案不同、提示词就不同"的题；问不出来就跳过，不凑数

按优先级补信息：

1. 成功标准：做成什么样算好，怎么验收
2. 范围：做什么、不做什么，边界在哪
3. 条件：给 agent 什么输入材料，有什么硬约束（技术、时间、风格、环境）
4. 产出：交付物形态、格式、语言、长度

节奏：

- 每轮问完一句话小结"已确认：…"，再决定要不要问下一轮
- 用户答"不清楚/随便"→ 自己定合理默认，不追问第二遍
- 最多 3 轮，宁可标假设也别把用户审问烦了
- 用户说"够了/直接出"→ 立刻停，进下一步

## 3. 写提示词

按下面结构写，按需删减，"目标"和"验收标准"必须有：

```
# 角色
一句话：身份 + 专长。

# 目标
一句话，写成可验收的结果。

# 背景
已确认的现状、材料、上下文。

# 输入
agent 会拿到什么（文件 / 数据 / 链接 / 无）。

# 任务
编号步骤，顺序明确，每步可执行。

# 约束
必须做的、不许做的、硬限制。

# 输出
交付物形态、格式、语言、长度。

# 验收标准
逐条可打勾。
```

写法要求：

- 自包含：agent 零反问能开工
- 具体可执行：不写"优化一下"，写"首屏加载压到 2 秒内"
- 没问到的信息标【假设】：如【假设】目标平台是手机浏览器，不对请改
- 每句话都承载信息，删掉客套和重复

## 4. 交付

- 提示词放一个代码块里，方便整体复制
- 代码块外用两三句说明：补清了哪些关键点、哪些是假设
- 问一句：要不要直接拿去执行
