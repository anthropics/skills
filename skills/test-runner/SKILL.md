# Test Runner

코드를 수정하지 않고 현재 변경과 관련된 자동 검사를 실행한다. 실패를 고치거나 의존성을 설치하지 않는다.

## 안전 규칙

- 저장소 지침과 패키지 스크립트를 먼저 확인한다.
- DB reset, seed, migration 적용, 배포, 운영 인프라 접근을 실행하지 않는다.
- 개발 서버나 브라우저를 자동으로 시작하지 않는다.
- 누락된 도구나 라이브러리를 사용자 승인 없이 설치하지 않는다.
- 환경 변수나 비밀 파일을 읽지 않는다.
- 요구 버전이 정해져 있으면 런타임 버전을 먼저 확인한다.

## 실행 순서

현재 변경과 관련된 검사만 다음 순서로 실행한다.

1. 타입 검사 또는 정적 검사
2. 린트
3. 관련 단위 테스트
4. 전체 단위 테스트
5. 구성되어 있는 E2E 테스트
6. 필요한 경우에만 빌드

앞의 저비용 검사 실패가 뒤 검사 결과를 무의미하게 만들면 중단하고 이유를 기록한다. 검사들은 서로 독립적이고 추가 비용이 작을 때만 계속 실행한다.

우선 `package.json`, `Makefile`, `pyproject.toml` 등 프로젝트가 선언한 스크립트를 사용한다. 선언된 스크립트가 없어도 설치된 의존성과 설정 파일이 확인되면 안전한 비대화형 명령을 사용할 수 있다.

명령은 다음 순서로 결정한다.

1. 저장소 지침(`AGENTS.md`, `CLAUDE.md`, `CONTRIBUTING.md`)에 적힌 검사 명령
2. 프로젝트가 선언한 스크립트
3. 확인된 설정 파일과 락 파일에 맞는 표준 비대화형 명령

패키지 매니저는 락 파일로 판별한다. 명령을 실행하기 전에 런타임 버전 요구사항(`.nvmrc`, `engines`, `.python-version` 등)이 있으면 먼저 확인한다.

설정이나 스크립트로 확인되지 않는 검사는 설치하거나 추측하지 말고 `NOT_CONFIGURED`로 보고한다.

## 출력 형식

각 검사마다 다음 내용을 기록한다.

- 검사 이름
- 실행 명령
- 상태: `PASS`, `FAIL`, `BLOCKED`, `NOT_CONFIGURED`, `SKIPPED`
- 종료 코드
- 핵심 출력 또는 첫 실패 원인

마지막에 전체 판정과 실행하지 못한 검증 공백을 요약한다. 테스트 통과만으로 서비스 로직과 사용자 의도가 모두 검증되었다고 단정하지 않는다.
